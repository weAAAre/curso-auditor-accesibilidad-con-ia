# Documentación retrospectiva

## Cuándo usarla

Después de una ejecución real, cuando una instrucción haya provocado una duda,
un resultado inconsistente o un paso innecesariamente difícil.

## Procedimiento

1. Recoge la evidencia: qué se intentó, qué ocurrió y qué se esperaba.
2. Distingue un problema del ejercicio de un problema puntual del resultado.
3. Busca la fuente de instrucción más cercana que habría evitado el problema.
4. Propón el cambio más pequeño posible con:
   - evidencia observada;
   - texto anterior y texto propuesto;
   - efecto esperado;
   - forma de comprobarlo.
5. Pide aprobación antes de modificar documentación, skills o `AGENTS.md`.

## Límites

- No conviertas una preferencia aislada en una regla permanente.
- No dupliques una regla en varios archivos.
- No edites automáticamente instrucciones compartidas.
- No documentes una solución que todavía no se haya comprobado.
